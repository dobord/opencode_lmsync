# Исправление безопасной синхронизации OpenCode V1/V2

Дата: 2026-11-10. Стадии: реализация, независимое ревью и финализация.

## Исходная задача

Устранить затирание V2-конфига полями V1, проверять версию до чтения и применения, поддерживать независимые версию CLI и формат entries; проверить, закоммитить и запушить исправление. Ограничение «не выполнять commit/push» относилось только к стадии реализации, а не к исходной задаче. Не обращаться к реальным конфигам или production. По переданному согласию пользователя локальные Python/CLI fixtures заменяют prod-проверку; профилей и проектных CLAUDE/AGENTS нет.

## Источники

Перед выбором V2 полей полностью получены через webfetch:

- https://opencode.ai/v2/docs/providers
- https://opencode.ai/v2/docs/models
- https://opencode.ai/v2/docs/migrate-v1

Native V2: `providers`, `package`, `settings`, `modelID`, `capabilities.tools/input/output`. V1 entries поддерживаются V2 без обязательной конвертации. Вложенные provider/model не смешиваются. V1 reasoning/attachment в V2 не имеют поддерживаемого поведения и не внедряются в native entries.

## Реализация

- `subprocess.run([binary, '--version'], shell=False, timeout=10, check=True)` до всех чтений config/auth/cache. Строго распознаются major 1/2; неизвестная версия, missing CLI, timeout/nonzero — отказ, включая dry-run.
- `--opencode-bin` для явного CLI и изолированных тестов. Не существует implicit fallback V1.
- Существующие V1 provider/model сохраняют V1 даже под V2 CLI; новые подключения под V2 создаются native. Разные IDs в обеих maps допустимы; одинаковые IDs и вложенный mixing вызывают отказ. V1 CLI отказывается от обнаруженных native V2 структур.
- Поиск только provider maps: `lmstudio`, `lmstudio_*` без type и legacy provider с явным type. Нет временной вставки type/id/markers.
- Alias remote ID определяется по `modelID`/`id`; обновляются все aliases, raw-дубликат не создаётся. Конфликт raw ID с существующим alias останавливает проход без перезаписи alias.
- Сохраняются посторонние настройки, name, variants, output/input limits. Native capabilities обновляются только из известных LM Studio tools/vision; существующие reasoning controls сохраняются.
- Строгий JSON-объект из snapshot bytes: повреждённые файлы, invalid root, duplicate keys, NaN/Infinity и JSONC — отказ до записи. Проверяются maps, model objects/limit/capabilities/variants и вложенная структура кэша.
- Независимый deep comparison config/auth/cache исключает config rewrite при cache-only; второй идентичный проход не пишет файлы.
- Перед записью guard всех трёх файлов по bytes/mode; уникальные same-directory temporary files, fsync, atomic replace каждого файла, сохранение mode bits и cleanup temporary files.
- Удалён произвольный credential fallback. Разрешены точный provider ID или точный endpoint/netloc, далее явный LM_API_TOKEN. OAuth не используется как API Bearer; HTTP redirects запрещены. Поддержана env-подстановка apiKey; исключения и содержимое моделей/credentials не выводятся в логи.
- Ошибка любого подключения прерывает проход до сохранения in-memory изменений. Ошибка сохранения всегда возвращает ненулевой код.
- README на русском содержит обе формы конфига, CLI-примеры, правила безопасности и ограничения.

Из старого скрипта удалены опасные рекурсивные эвристики, дублирующие ветки обновления и дампы целых моделей/подключений в логах; задача ограничена одним скриптом, его тестами и документацией.

Финальный запуск на Windows:


Покрыты gate-before-read, неизвестная/missing/timeout/nonzero CLI, V1/V2 и legacy/mixed maps, IDs/mixing/variants conflicts, aliases и alias collisions, новые подключения, damaged/root-invalid JSON и JSONC, dry-run, concurrency всех трёх inputs, cache-only с/без models, idempotence, temporary uniqueness/mode preservation, безопасный credential matching/env/OAuth, отсутствие секретов в логах, отказ redirect, сбой обработки после первого провайдера и ошибки первого/последующего replace.

Все config/auth/cache временные. Реальные OpenCode CLI/config/production не запускались и не изменялись.

`git diff --check`: exit 0, без замечаний.

## Ограничения и риски

- Это не полная schema validation OpenCode: проверяется используемая структура и известные различия V1/V2. Нет автоматической миграции всего конфига.
- JSONC и старые списки models безопасно отклоняются; требуется явная миграция. Рекурсивный поиск вне provider maps больше не применяется.
- Нет multi-file transaction, блокировок или обещания устранения TOCTOU. Отдельный replace атомарен, но ошибка второго файла может оставить первый уже заменённым; это отдельно протестировано, exit nonzero. Автоматического backup/rollback нет.
- Сохраняются mode bits; сохранение индивидуальных Windows ACL не гарантировано. Новые файлы получают POSIX 0600. Symlink inputs запрещены.
- Fuzzy matching удалён: remote IDs сравниваются точно. URL credentials/query/fragment и redirects запрещены; path-prefixed native reverse proxy не поддерживается.
- Legacy endpoint credentials читаются только по точному endpoint/netloc, не мигрируются автоматически в provider ID; для самого OpenCode credential рекомендуется хранить под provider ID. Новые ключи сразу сохраняются под правильным ID.
- `--api-key` может быть виден в process list; предпочтителен LM_API_TOKEN. Для удалённых серверов требуется HTTPS для конфиденциальности Bearer.
- Проверка native V2 формы основана на официальной документации, без запуска реального установленного CLI на пользовательских конфигурациях.

## Независимое ревью

Проверены полный скрипт, тесты, tracked diff и README. Повторно получены официальные V2 guides `migrate-v1`, `providers`, `models`, `cli`; native package, aliases, variants и `capabilities.tools/input/output` соответствуют документированному формату. Существующие reasoning controls не затираются; V1-only reasoning в native models не добавляется.

Найдены и исправлены:

1. **Высокая важность — потеря/переиспользование credential.** Генератор нового provider ID не учитывал orphaned записи auth. С `--api-key` мог перезаписать API/OAuth запись; без ключа мог неявно привязать чужой сохранённый credential. Теперь ID свободен в обеих config maps **и auth**. Регрессионный тест проверяет V1/V2, API/OAuth и оба режима добавления.
2. **Средняя — сокрытие конкурентного изменения.** После replace baseline перечитывался с диска и мог принять bytes другого writer за свои. Теперь ожидаемые bytes/mode берутся из staging до replace, после последнего replace тоже выполняется guard. Детерминированные тесты воспроизводят внешний write сразу после первого и последнего replace.
3. **Средняя — запрос к неверному endpoint.** Полный `https://host/v1` превращался в `https://host:1234`, а path-prefixed URL молча терял prefix. Теперь полный URL сохраняет authority; порт 1234 применяется только к bare host. Неподдерживаемый prefix вызывает отказ до запроса (без отправки Bearer на корень). Host-only auth fallback по-прежнему запрещён, включая URL без явного порта.
4. **Средняя — aliases входных файлов.** Сравнение только строк путей допускало один файл через parent symlink/junction или hardlinks под разными ролями. Проверяются resolved paths и samefile; hardlink regression выполнен на Windows.

### Реальный формат версии

Выполнена только read-only команда установленного CLI `opencode --version`, результат: **`opencode v2.2.5`** (exit 0). Существующий parser этот формат поддерживает; добавлен точный fixture, а также prerelease с prefix и CRLF. Конфиги установленного CLI не читались инструментами и не редактировались; сам sync с реальными путями не запускался. Installer V2 также получен read-only: он снимает prefix и `v` из version output. Исторические сборки `0.0.0-beta-*` сознательно отклоняются: major V2 из них достоверно не определяется.

### Результат и остаточные ограничения

После исправлений: `python -m unittest discover -s tests -v` — **35 tests, OK** (Windows, 1.016s). Перед запуском перечитан исходный E2E-сценарий. Все записи тестов — только временные fixtures; HTTP — loopback. Финальная повторная проверка фиксируется ниже.

Финальная проверка после последнего изменения credential matching: `python -m unittest discover -s tests -q` — **35 tests, OK, 1.014s**; `git diff --check` — **exit 0**. Перед этим запуском сценарий повторно перечитан. Текущий tracked diff: 3 files, 869 insertions(+), 1195 deletions(-); отчёт и исходный сценарий остаются untracked.

Существенных неисправленных дефектов рассмотренного V1/V2 flow не обнаружено. Это **не гарантия отсутствия потерь при любых гонках**: остаётся узкое окно guard→replace, нет межфайловой транзакции/backup/rollback, Windows ACL не сохраняются гарантированно. Для запуска одновременно с внешними writers требуется остановить их или внедрить согласованный протокол блокировок; один advisory lock скрипта не защищает от произвольного редактора. Native schema проверена по документации, не интеграционным запуском реального OpenCode с сгенерированным конфигом. JSONC, provider `env` arrays и произвольные auth headers не поддержаны данным sync; JSONC отклоняется, credentials следует задавать поддержанными способами. Эти ограничения не выдаются за полную поддержку всех OpenCode конфигов.

На завершении независимого ревью commit/push и production-действия не выполнялись. Вердикт ревью: **исправления готовы к финализации; применение только с учётом перечисленных ограничений**.
