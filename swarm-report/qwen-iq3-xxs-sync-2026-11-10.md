# Qwen3.8 27B IQ3_XXS: диагностика и исправление синхронизации

## Воспроизведённая причина

- Установлен OpenCode V2; пользовательский конфиг содержит legacy `provider` entries, которые сохраняются в исходном формате.
- `GET /api/v1/models` сервера `192.168.1.82:1234` возвращает отдельные точные ключи `qwen3.8-27b@iq3_xs`, `qwen3.8-27b@iq3_xxs`, `qwen3.8-27b@iq4_xs`. Парсер различает их правильно.
- У `iq3_xxs` максимальный контекст 262144, фактический loaded-instance context — **135168**. Веса уже загружены в LM Studio; ошибка относится к регистрации в OpenCode, а не к скачиванию/загрузке весов.
- В исходном конфиге присутствовали XS и IQ4_XS, но отсутствовал XXS.
- Следующий провайдер, `lmstudio_192_168_1_12_1234`, недоступен. Строгий проход останавливался до `write_changes`, отбрасывая в том числе успешно обнаруженные модели первого сервера. Исходный `--dry-run --verbose` воспроизвёл отказ; диагностика не называла проблемный provider ID.

## Исправление

- Строгое поведение по умолчанию сохранено: сетевой сбой по-прежнему отменяет запись всего прохода.
- Явный `--skip-unavailable` разрешает обработать доступные серверы, сохраняя записи недоступных. HTTP/auth errors, redirects, некорректные ответы и ошибки обработки не пропускаются. Если недоступны все выбранные серверы — exit 2 и никакой записи.
- Повторяемый `--connection PROVIDER_ID` позволяет обработать только нужные подключения. Неизвестные IDs и сочетание с `--add-connection` отклоняются до сетевых запросов.
- Ошибки запросов называют provider ID; успешные подключения показывают количество обнаруженных/добавленных моделей и loaded contexts. Секреты и тела ответов не логируются.
- Разделены транспортные ошибки и HTTP/response failures. Безопасное сохранение, snapshots, guards, формат V1/V2 и точное сопоставление ID не изменены.

## Реальное применение

1. `--skip-unavailable --dry-run`: 8 LLM, 3 новых модели, 1 loaded context; второй сервер пропущен; запланированы изменения config/cache.
2. До записи сделана резервная копия конфига и кэша: `C:\Users\Dobord\AppData\Local\Temp\opencode\lmsync-before-84025aj9`. Auth в резервную копию не копировался и не изменялся.
3. `python scripts/update_lmstudio_models.py --skip-unavailable`: успешно сохранены config/cache. Добавлены `qwen3.8-27b@iq3_xxs`, `gemma-4-12b-it`, `unsloth/qwen3.8-27b`.
4. Программно проверены ID XXS и context 135168, равенство всех остальных providers/top-level settings, посторонних cache entries и побайтовая неизменность auth.
5. Повторный реальный `--connection lmstudio_192_168_1_82_1234`: нет изменений; config/auth/cache побайтово идентичны состоянию после первого прохода.
6. `opencode api get /api/model`: exit 0; OpenCode уже возвращает XXS с `providerID=lmstudio_192_168_1_82_1234`, `modelID=qwen3.8-27b@iq3_xxs`, context 135168, tools=true, input=text/image. Перезапуск сервиса не потребовался.

Недоступный сервер не синхронизирован; это явно отражено в предупреждении. Генерация текста не запускалась: проверены native metadata, сохранение и фактическая видимость модели в OpenCode API. Пользовательские конфиги, резервные копии и секреты не включаются в git.
